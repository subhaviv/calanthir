Demo Setup — Loom vs the Platform

Two layers, one registry between them. The platform is the governed factory; Loom is the human-facing storefront. The registry is the source of truth both sides agree on.

Responsibilities

who owns what

Loom Console

Control plane · the storefront
📁Browse the catalog. Registry Agents / Tools / Skills read the GA registry (source of truth).
⬇Import a registry agent. “Not in Loom” → Import → ARN / region → DB row keyed on registry_record_id.
🔄Sync. Reconciles imported agents to the live registry on demand (registry wins).
🏷Imported / Not-in-Loom indicator. Shows whether a registry agent has a local operational record.
⚙DB = operational cache. Runtime state — endpoint status, sessions, deploy status — the registry can’t hold.
🚫Agent creation hidden (config). VITE_LOOM_AGENT_CREATION_ENABLED=false — Loom discovers & imports, it does not mint agents.

Platform (blueprint) Factory

Landing zone · the paved road
🏛Accounts & SCPs. AgenticAI-Workloads OU + 8 Service Control Policies the BU can’t override.
🔨Builds & deploys agents. CI/CD pipeline + ~28 phase-* conformance gates fail at synth, not in prod.
📒Owns the GA registry. RegistryStack creates it; publishes governed records (ARN, Cedar policy, ownership).
✅Schema intake + approval. Validates the record; DRAFT → APPROVED → discoverable.
🛡Runtime controls. Cedar authz, guardrails, kill-switch, observability — per invocation.
🏢Workload accounts. The agent actually runs here (AgentCore Runtime + endpoint).

The bridge — the Registry

how the two layers connect

Platform publishes governed records → Loom reads them → import pulls the record into Loom’s operational DB. One-directional: catalog / identity flows platform → registry → Loom; operational state stays in Loom’s DB.

Platform deploys agent → Registry record (APPROVED) → Loom reads registry → Import → DB row → Sync keeps it current

The line

autonomy vs governance
Loom ownsDiscovery, import, operational state (sessions / status), the human console. “What’s running and how do I use it.”
Platform ownsAccounts, guardrails, pipeline gates, the registry, approval. “What’s allowed to exist and how safely.”
⚠ For this demo: agent-creation in Loom is turned OFF by config, so the story stays clean — the platform is the only thing that mints agents; Loom discovers, imports, and operates them. Registry is single-bound (one registry) for now. DB starts empty, so everything visible comes from the registry — that’s the point, not a bug.
