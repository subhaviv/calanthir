AgentCore SDLC — Which Controls, When

A practical dev→prod roadmap: some controls are on from day 0 (they cost no speed), others phase in as the environment gains real data and real connectivity. The platform turns each on at the right stage — teams inherit the posture instead of re-deriving it.

ⓘ The dividing line is blast radius, not developer convenience. auth=None is safe in dev not because dev is low-stakes — but because the dev cell is isolated with no real data and no production connectivity. The moment either appears, the control must too.

Two buckets

the mental model behind the table
✅ ON from day 0 — never relaxed
  • Guardrail content scanning — an agent is semi-trusted (prompt-injection-steerable) from its first run.
  • Model allow-list — no ungoverned model access, ever.
  • 5-tag attribution — free upfront; painful to retrofit.
  • Registry-approved tools only — gateway wires only to approved targets.
  • Dev-cell isolation — this is what makes relaxing the others safe.
⏳ Phase in — gated on real data / real callers
  • Authentication (Custom JWT)Trigger: shared services or any non-synthetic data — not a calendar date.
  • Private connectivityTrigger: data worth protecting in transit, or a private dependency.
  • Strict / gated evalsSmoke → full suite → fail-closed gate.
  • Real dataSynthetic → masked → real — each step gated by the controls above first.
⚠️ The real risk isn’t auth=None in dev — it’s config drift. A loose dev setting silently surviving into an environment that gained real data. The platform makes that structurally impossible: no direct-deploy, and the conformance gate fails a prod-targeted stack that still has auth=None, a public endpoint, or a missing guardrail — before it deploys.
